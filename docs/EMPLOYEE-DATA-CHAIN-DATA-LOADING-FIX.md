# Employee Data Chain — Data Loading and Button Fix

**Date:** 31 October 2026  
**Project:** PeopleDesk — Employee Record Management System

## Finding: “Not found”

Chrome Network inspection captured the browser request while signed in as the HR account:

| Property | Observed value |
|---|---|
| Request URL | `http://127.0.0.1:8080/api/dsa/employee-chain` |
| Method | `GET` |
| Status | `404 Not Found` |
| Response body | `{"error":"Not found"}` |
| Browser console | `Failed to load resource: the server responded with a status of 404 (Not Found)` |

The frontend then displays the API's `error` field in the Employee Data Chain view. It is not replacing the page with an HTML 404. Authentication is active (the page shows `hr-admin`, role HR); an authentication failure would be 401 and a role denial would be 403.

The browser request matches the current code. `app.js` calls `api('/dsa/employee-chain')`; the shared helper issues a same-origin `fetch` and resolves this to `/api/dsa/employee-chain` with method GET. `LocalServer.handle` authenticates `/api/*` before dispatching GET requests to `ApiController.get`. `ApiController.get` strips the `/api` prefix and contains a branch for `/dsa/employee-chain` that calls `EmployeeChainController.get`. That controller allows HR/Admin and returns `{employees, initialIds}`. The response shape matches the frontend.

Therefore the 404 was from the Java handler that had been running on port 8080, whose loaded `ApiController` did not include the route present in this project source. The project’s Phase 6 report records that port 8080 was already occupied during the newer source checks, which were run on port 8081. Rebuilding assets does not replace Java classes already loaded in the running JVM. This was a runtime/source version mismatch, not a wrong frontend URL or an HR authorization issue.

## Change made

The existing `.employee-chain-card` now aligns its single button to the card’s start and no longer forces the old tall card height. `.employee-chain-launch` no longer sets `width:100%` or a 76px minimum height, so the existing green primary button uses its normal compact sizing and padding. The button label and click handler remain **Employee Data Chain** and `openEmployeeChain()`.

No Java controller or data-structure source was changed: the route and functionality already exist in the current source. `EmployeeChainDemo` continues to wrap the genuine `SinglyLinkedList<Employee>`, resolves selections against PeopleDesk employee records, and isolates all operations from `AppData.employees`.
